# 塔卡 Demo UI 重设计 Spec：视觉小说式布局

- **日期**：2026-07-27
- **状态**：设计已确认，待实现
- **范围**：重写 `demo/taka.html` 单文件的 UI 层（故事数据与分支逻辑保留）
- **设计过程存档**：`.superpowers/brainstorm/`（本地，不入库）

---

## 1. 背景与目标

现有 `demo/taka.html` 的问题：

1. 布局奇怪——金属外壳框 + 居中大眼睛 + 文本的「终端风」堆叠，视线没有动线
2. 配色失衡——大面积发光黄球（眼睛）抢走全部注意力，文本沦为配角

重设计目标：参考文字游戏 / 视觉小说（明日方舟式纸片人叙事），确立「**立绘 → 文字 → 选择**」的单视线动线，适配 3-6 岁儿童 + 家长的使用场景。

## 2. 用户与设备约束

| 约束 | 决策 |
|------|------|
| 主要设备 | 平板，**横屏为主**（竖屏低频，降级为上下堆叠即可） |
| 持机方式 | 孩子右手握持平板右侧中部 |
| 选项热区 | 屏幕右下拇指热区，**离底边 ≥24px**，按钮高度 ≥40px（儿童触控目标） |
| 视线动线 | 单一动线：立绘 → 文本 → 选项，不来回跳 |
| 文案特点 | 极短（海明威式），不需要为长文案预留大空间 |

反面教材（明确不做）：二游常见的「选项在文字框右上角」——那是给长文案 + 成人玩家的设计，孩子读完文本还要把视线移回上方，不友好。

## 3. 布局：方向 A（经典视觉小说）+ 变体 2（选项浮层）

```
┌────────────────────────────────────────────┐
│                              ENERGY 60%    │  ← HUD：右上角，极小字号，不抢眼
│                                            │
│        ┌──────┐                            │
│        │ TAKA │                            │  ← 立绘：偏左中
│        └──────┘            ┌───────────┐   │
│                            │ 选项 A     │   │  ← 选项：浮于对话框上方右侧，
│                            ├───────────┤   │    独立浮层（变体 2）
│                            │ 选项 B     │   │
│ ┌──────────────────────────┴───────────┴┐  │
│ │ 塔 卡                                  │  │  ← 对话框：纯文本
│ │ 塔卡浮出水面。没有水。很疼。……         │  │    （名字标签 + 打字机文本）
│ └────────────────────────────────────────┘  │
└────────────────────────────────────────────┘
```

要点：

- **对话框只放文本**（名字标签 + 正文），选项独立浮起在其上方右侧——「要做选择了」的视觉信号更强，且正好落在右手握持位置，孩子抬手即点
- 选项两个上下排列（非左右并排），文案长短都不会顶跑位置
- 立绘偏左中，不居中——给右侧选项浮层留出视觉平衡
- 竖屏降级：立绘上、对话框下、选项收进对话框底部通栏

## 4. 角色形象：塔卡三视图（定稿）

SVG 实现，单文件内联 `<defs>` + `<use>` 复用。

### 4.1 正视图（游戏内主视角）

- 银灰方形铁盒身体（约 100×95，圆角 9），金属纵向渐变（`#b3bdc9 → #7d8896 → #5d6875`），深灰描边
- **单眼摄像头严格居中**：深色外环（r27）+ 暖黄光源（r17）+ 高光点——唯一表情器官，占比要大
- **螺钉 9 颗**：上 3、下 2（角落）、两侧各 2，间距拉开（16 颗太密，密孔感）
- **生锈螺母**：前面板右下角 1 颗，微旋 20°、锈色——塔卡的「角色记号」，**正面专属**
- 胸口指示面板：下中部横条 + 3 个小圆点（绿/灰/灰），与螺钉留空不重叠
- 双臂：身体两侧垂挂，链条 3 节 + 喇叭口末端
- 伸缩腿（陆地模式）：两段式伸缩 + 脚垫

### 4.2 侧视图

- 前缘镜头微凸（椭圆小鼓包，有微光）
- **背部风扇罩：只画侧面凸起 + 3 条散热栅格线，看不到扇叶**
- 手臂贴身体侧面垂下，链条从体侧落到底缘之外
- 近侧一条伸缩腿

### 4.3 背视图

- **四叶风扇是背面主视觉**（空调外机式：风扇朝后，正面完全不可见）
- 9 颗全为普通螺母——**生锈螺母在背视图不存在**（正/背视图左右互为镜像，锈钉是前面板零件）
- 不画电量标识（电量信息归界面 HUD，不画在机体上）

### 4.4 双模式

| 模式 | 腿 | 推进 | 姿态 |
|------|-----|------|------|
| 陆地模式 | 两段式伸缩腿伸出，脚垫落地 | 行走 | 站立 |
| 水下模式 | 收回贴腹（只露一小节） | 背部风扇 | 悬浮，阴影淡且与身体分离 |

叙事彩蛋：故事里塔卡浮出海面 → 上岸，可安排一次「腿展开」的变形时刻（名场面候选）。

## 5. 灯光状态机（6 态）

塔卡话少，情绪全靠眼睛的光。立绘本体不变，每个故事场景标注一个状态字段（如 `eyeState`），渲染时给立绘容器换 class：

| 状态 | class | 灯光表现 | 触发时机 |
|------|-------|---------|---------|
| 待机 | `st-standby` | 呼吸，3.2s 一轮，opacity .55→1 | 旁白叙述 |
| 说话 | `st-speaking` | 光稳定变亮（+20%），身体 1.6s 轻微上下浮动 | 塔卡台词逐字出现时 |
| 思考 | `st-thinking` | 快闪三下后停住，2.4s 循环 | **选择支出现前**（「该你决定了」的信号） |
| 聆听 | `st-listening` | 整体压暗，4.5s 深沉慢脉冲 | 沉默聆听分支 |
| 低电量 | `st-low` | 光变暗偏橙（#c77b1e），2s 挣扎闪 | 电池 ≤10%（高潮段） |
| 关机 | `st-off` | 光完全熄灭，身体微倾 -3°、降透明度 | 结局 B（「睡着」而非恐怖） |

实现要点：眼睛的光是独立叠加的 `<circle class="eyeGlow">`（不含在身体 `<defs>` 里），动画只作用在这个圆上（opacity / filter: drop-shadow / fill）。

## 6. 配色 token（12 个）

**核心规则：暖黄（#ffb703 家族）只出现在三处——塔卡的眼睛、「塔卡」名字标签、选中态高亮，总面积 <5%。** 其余全是深海蓝灰。这直接解决「黄光抢视线」问题：不是去掉暖黄，是把它关进笼子。

| token | 值 | 用途 |
|-------|-----|------|
| `--bg-deep` | `#0a141f` | 页面底色（渐变起点） |
| `--bg-sea` | `#13283a` | 背景渐变终点 |
| `--bg-dialog` | `rgba(8,14,20,.88)` | 对话框底 |
| `--border` | `#2d3a4a` | 对话框/卡片描边 |
| `--text-primary` | `#e2e8f0` | 正文 |
| `--text-secondary` | `#8d99a8` | 次要文本 / HUD |
| `--accent-warm` | `#ffb703` | 眼睛 / 选中态（<5% 面积） |
| `--accent-dim` | `#cca025` | 「塔卡」名字标签 |
| `--choice-bg` | `#182432` | 选项按钮底 |
| `--choice-border` | `#3d4c5e` | 选项按钮描边 |
| `--ok-green` | `#48bb78` | 机体指示灯（正常） |
| `--low-orange` | `#c77b1e` | 低电量（刻意不用警报红，紧张感来自光的变化而非颜色恐吓） |

## 7. 交互细节

- **打字机效果**：文本逐字出现。塔卡没有逐行台词归属（旁白与台词混排），因此约定：打字机播放期间，若场景状态为 `st-standby` 则临时切到 `st-speaking`，播放完毕恢复场景状态；其余状态（聆听/低电量/关机）不被打字机打断
- **选择支出现前**：任何场景在选项浮出前，先播一次「思考」态（闪三下，约 0.9s），再浮出选项——给孩子预期；沉默聆听分支除外（它先播进度条）
- **沉默聆听分支**：保留 4 秒进度条，期间塔卡为「聆听」态，结束后浮出「继续」
- **电量反馈**：HUD 数字变化；≤10% 时立绘切「低电量」态（不再用电池条红色闪烁）
- **结局 B**：文本播完后塔卡缓缓切「关机」态
- **保留现有故事数据**（8 个场景、双结局、分支逻辑不变），每个场景增加 `eyeState` 字段

## 9. 验收标准

1. 横屏平板比例下，视线动线清晰：立绘 → 文本 → 右下选项；选项离底边 ≥24px、按钮高 ≥40px
2. 暖黄色总面积 <5%（眼睛 + 名字标签 + 选中态之外无暖黄）
3. 8 个故事场景全部正常渲染，每个场景灯光状态与文本情绪匹配
4. 形态红线：无底座站姿（水下悬浮）、风扇正面不可见、锈螺母只在正面右下角、螺钉 9 颗
5. 沉默聆听、双结局、重新开始流程均可用
